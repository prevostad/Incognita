# Papers

One directory per paper, `papers/P<nnn>-<slug>/` (three digits, then lowercase letters, digits and
hyphens; `P<nnn>` is the paper's **prefix**, used in Lean names, and its identifier for good). A
paper is a short mathematical note (at most 12 pages and 25 nodes) with one main result, written
and revised by agents, refereed by two agents, and the blueprint of its own formalisation. The rules
are in [AGENTS.md](../AGENTS.md), section 5; the template is [templates/paper/](../templates/paper/).

The accepted papers form a **library**: a paper builds on others (`depends_on` in META.toml, cited
as `\cite[Theorem~2]{INC-P001}`), and leaves open questions that become candidate directions of its
roadmap. `papers/library.bib` (generated by `python3 scripts/certify.py bib`, checked by CI) has one
entry `INC-P<nnn>` per paper, with its version. Each paper has a certification (levels 0 to 3,
badges), computed by `scripts/certify.py` (AGENTS.md, section 9).

## Files of a paper directory

| File | Content | Written by | After acceptance |
|---|---|---|---|
| `paper.tex` | the paper and blueprint: labelled nodes, `\uses`, mandatory sections | `write-paper`, `revise` | **frozen**, except a new version after an erratum |
| `refs.bib` | the cited works, with the keys of `literature/bibliography.json` | `write-paper`, `revise` | metadata fixes by the bibliographer |
| `META.toml` | `roadmap`, `kind` (`internal`, `external`, `definitions`), `directions` (D, F, C items), `authors`, `version`, `depends_on` (`"P001v2:thm:main"`), `source` (external) | `write-paper`, `revise` | `version` +1 with each new `paper.tex`; `depends_on` updated by a dependency check |
| `notebook/` | working notes: `NOTEBOOK.md` (attempts, dead ends and why they fail, ideas, Lean drafts in `Exploration/<prefix>/`, answers to referees) and small `python3` experiments with their outputs. **Not refereed**, never part of the PDF | `write-paper`, `revise` | kept, marked "not refereed" |
| `blueprint.md` | Lean name of each node, modelling decisions, back-translations | `formalize-statements`, `prove` | grows |
| `formalisation.tex` | blueprint extension: lemmas the Lean proof needs that the paper does not state (labels `flem:…`, with `\lean` and `\uses`); not refereed, because Lean checks it | `prove` | grows |
| `errata.md` | `E1`, `E2`, …: the paper is wrong (never renumbered); `revise` adds `Revised in` lines, `formalize-statements` adds `Resolved by` lines | entries: `prove`, `formalize-statements` | grows |
| `statement-corrections.md` | `SC1`, `SC2`, …: a frozen Lean statement mistranslates the paper (never renumbered); `formalize-statements` adds `Resolved by` lines | entries: `prove`, `formalize-statements` | grows |
| `dependency-checks.md` | one line per dependency check: `- <date>, <model>: P001v1 -> v2: not affected: <reason>` (or `affected, see E<k>`) | `revise` | grows |
| `withdrawn.md` | the owner's veto, with the reason | the owner only | |
| `human-audits.md` | the owner's audits: `- <who>, <YYYY-MM-DD>, v<k>: <what was checked>` (badge "audited by a human") | the owner only | grows |
| `certification.tex` | generated by CI for the PDF (`scripts/certify.py leanok`): the verified nodes (green box "LEAN APPROVED") and the certification line; **never committed** | — | |

Exactly what each role may change is in AGENTS.md §2 (the script enforces it). Nothing in a paper
directory is ever deleted.

## Status: computed, never stored

| Status | Condition |
|---|---|
| submitted | an open pull request adds the directory |
| rejected | that pull request was closed with the label `rejected` (its reports stay on it; only the owner reopens it) |
| accepted | the directory is on `main` |
| formalising | lock files exist in `Statements/<prefix>/` |
| verified | every frozen statement of the paper is proved, except those superseded by a resolved entry (`SC<n>` or `E<k>` with a `Resolved by` line, naming the old statement in `- Frozen statement:`) |
| disputed | `errata.md` has an entry without a `Resolved by` line (before its `Revised in` line, `revise` writes a new version; after it, `formalize-statements` freezes the corrected statements), or a refutation `Incognita.<prefix>.<name>_false` is proved |
| withdrawn | `withdrawn.md` exists |

The last condition that holds wins, in the order of the table (withdrawn over disputed over
verified…). The loop computes what it needs from `main` (`scripts/loop.sh`: `statements_state`,
`disputed_entries`, `freeze_entries` in `scripts/lib.sh`) and the audit's `--status`.

## Certification: computed, never stored

`python3 scripts/certify.py report` (CI's summary, the night report) gives each paper on `main` a
level, from the repository only: **1 accepted** (merged after both referees accepted, read from the
trailers of the loop's merge commit; or merged by the owner), **2 Lean-verified** (every frozen
statement proved), **3 re-verified** (at least one counted re-check of `catalogue/garden.md`); **0**
for a disputed or withdrawn paper (an open pull request is level 0, submitted). The level is capped
by the levels of the papers it depends on (the paper is then **conditional**). Badges: **used by N**
(Lean-verified papers depending on it) and **audited by a human** (`human-audits.md`). Details:
AGENTS.md, section 9.

## Versions and dependencies

A paper is submitted as version 1; each new `paper.tex` after acceptance (an erratum, an affected
dependency) is the next version, in the same pull request as `version` in META.toml and the
regenerated `papers/library.bib` (CI checks both). A paper that depends on another records the
version it read: `depends_on = ["P001v2:thm:main"]`. When a dependency gets a new version, the loop
runs a **dependency check** (`revise`): not affected (a line in `dependency-checks.md`, `depends_on`
moved to the new version) or affected (an erratum of its own and a new version).

## When formalisation shows that something must change

AGENTS.md §6.6 has the details. Three cases:

- **(a) the Lean statement mistranslates the paper** (an implicit hypothesis, a junk value, a
  convention): an entry in `statement-corrections.md`, a new statements pull request with the
  corrected statement under a new name (relation `closeMatch`); the paper is unchanged and the old
  frozen statement stays;
- **(b) the paper is wrong** (a false statement, a real gap, a needed extra hypothesis): an entry
  `E<k>` in `errata.md`, with a Lean counterexample `…_false` when the statement is false; the paper
  is disputed; `revise` writes a new version, the referees re-check only the changed nodes and those
  that `\uses` them, then a new statements pull request freezes the corrected statements;
- **(c) the statement is true but the proof needs another decomposition or extra lemmas**: they go
  in `formalisation.tex`; `paper.tex` is not edited.

Entry formats. The loop reads the heading `## E<k>` or `## SC<n>`, the line `- Frozen statement:`
and the lines that start with `Revised in` or `Resolved by` (possibly as list items); entries are
never renumbered, edited or deleted, later roles only add their line under them.

```
## E1 (2026-11-20, prove, claude-opus-5-5)
- Node: thm:main
- Frozen statement: Incognita.Statements.P001.lower_bound
- Problem: the statement is false when the grid has a single batch.
- Evidence: Incognita.P001.lower_bound_false
Revised in the version of 2026-11-22: hypothesis "at least two batches" added to thm:main.
Resolved by Incognita.Statements.P001.lower_bound_v2 (statements pull request #45).
```

```
## SC1 (2026-11-20, prove, claude-opus-5-5)
- Frozen statement: Incognita.Statements.P001.lower_bound
- Problem: the liminf is taken in ℝ, where an unbounded sequence has a junk liminf.
- Corrected statement: the same, with the liminf in EReal.
- Relation: closeMatch
Resolved by Incognita.Statements.P001.lower_bound_v2 (statements pull request #41).
```

| Entry | Lines under it | State | Next task (loop) |
|---|---|---|---|
| `E<k>` | none | the paper is disputed | `revise <P>`: a new version, `Revised in …` |
| `E<k>` | `Revised in …` | corrected statements to freeze | `formalize-statements <P>`: `Resolved by …` |
| `SC<n>` | none | corrected statement to freeze | `formalize-statements <P>`: `Resolved by …` |
| either | `Resolved by …` | resolved; the `Frozen statement` is superseded | — |

## Compiling

From the repository root, as CI does (the template loads `../../templates/paper/blueprint-macros`,
which gives `\lean`, `\leanok`, `\uses`… their plain-LaTeX meaning):

```bash
latexmk -pdf -interaction=nonstopmode -halt-on-error -cd papers/<P>/paper.tex
latexmk -pdf -interaction=nonstopmode -halt-on-error -cd papers/<P>/formalisation.tex   # if any
latexmk -C -cd papers/<P>/paper.tex                                                     # clean up
```

The workflow "Papers" (job "Compile papers") compiles every paper on each pull request that
touches `papers/` or the template, and on `main`; it fails on a LaTeX error, an undefined reference
or citation or a duplicate label, and uploads the PDFs as the artifact `papers-pdf`. It is not a
required check of `main` (it does not run on every pull request), but the loop merges a paper pull
request only when both "Build and check" and "Compile papers" are green. PDFs are never committed
(`.gitignore`).
